# Brain ED 0.2.0 — общая память для ваших ИИ-агентов

**Brain ED — локальная память, в которой ИИ-агенты сохраняют и находят решения, ошибки и контекст проекта между сессиями.** Пакет и команда называются `brain`.

При работе с Claude Code, Codex и Hermes Agent приходится повторять контекст в новых чатах. Brain даёт им общее место для решений, ошибок и свидетельств. Искать можно самому: `brain ask` не требует разговорной модели.

Разработчику Brain помогает меньше повторяться; в компании уполномоченный помощник получает выбранные факты по проектам. Командный режим предварительный: перед широким внедрением нужен пилот.

## Что нового

Полный список — в [CHANGELOG](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/CHANGELOG.md). Основные изменения по сравнению с предыдущей версией:

- **Из разговоров в память:** дистилляция решений, ошибок, тупиков, находок и планов со свидетельствами, ссылками на сессии и историей статусов. Локальные/API и подписочные провайдеры, предварительный просмотр, бюджеты, причины отклонения, продолжение обработки и отдельное расписание.
- **Поиск прошлой работы:** ограниченные выдержки архива в поиске памяти, даты на русском/английском и отдельные роли журнала. Вызовы/результаты/ошибки инструментов и видимые сводки рассуждений ограничены 2048 символами; скрытые рассуждения недоступны.
- **Факты для команды:** манифест выбирает получателей, пространства, классы и поля. Ограниченные срезы содержат разрешённые факты, задачи и метаданные Git. Ответы показывают источник, давность и покрытие; доступны обычные вопросы и MCP-инструменты чтения.
- **Явные соединения:** TLS, enrollment, проверка CA, роли, отзыв и корпоративный relay со сквозным TLS координатора. Прямой TLS сохранён; произвольный публичный NAT не проверен.
- **Понятнее настройки:** предварительный просмотр агентов/приватности/команды, история настроек, улучшения клавиатуры и фокуса, уменьшение анимации, офлайн-граф и диагностика. Визуализация описывает загруженную выборку.
- **Импорт и восстановление:** Markdown/wiki-ссылки и версии Graphify, расширенная общая маскировка, бэкапы и отдельные таймеры. Локальный OpenTelemetry-экспорт не отправляет телеметрию автоматически.
- **Проще установка:** инструменты статической Linux-сборки, установщик с SHA-256, руководства и справочник CLI. Наличие workflow не доказывает публикацию или проверку файла.

## Установка

Поддерживаемая платформа — Linux. Целевые сборки: Linux x86_64 и aarch64; ARM-бинарник также предназначен для Android/Termux. Это Linux ELF, не APK. macOS, затем Windows — в плане, в 0.2.0 они не поддерживаются. В Termux храните исполняемый файл в приватном HOME, вне общего хранилища Android. Нужны Bash, curl и coreutils; необязательные инструменты архива требуют Python 3. Совместимость с конкретным телефоном нужно проверять.

### Быстрая установка (две команды)

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/vavavadusik-crypto/brain-ed/v0.2.0/install.sh
bash install.sh --version 0.2.0
```

Скрипт проверяет SHA-256 скачанного бинарника и только потом ставит его в `~/.local/bin/brain`. Его можно прочитать перед запуском — он короткий.

### Установщик: одна команда установки

Получите `install.sh` из проверенного исходного тега `v0.2.0` или соответствующего checkout и прочитайте его. В каталоге со скриптом:

```sh
bash ./install.sh --version 0.2.0
```

Скрипт скачает по HTTPS подходящий `brain-0.2.0-<target>` и `SHA256SUMS`, проверит точную SHA-256 и установит `~/.local/bin/brain`. При установке скачанный бинарник не запускается. Не нужны sudo или Rust; модели, службы, подключение агентов и сбор архива автоматически не включаются. Сумма проверяет целостность загрузки, но не заменяет независимую подпись издателя.

Проверка без сети и записи: `bash ./install.sh --version 0.2.0 --dry-run`. Добавьте `export PATH="$HOME/.local/bin:$PATH"` в профиль оболочки. `--uninstall` удаляет CLI, сохраняя данные Brain.

Для загрузки нужны бинарники 0.2.0 и объединённый SHA256SUMS в файлах релиза. См. [контракт сборок](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/build-release.md).

### Вручную: бинарник и проверка суммы

Скачайте из файлов релиза `SHA256SUMS` и бинарник своей архитектуры. Для x86_64, из каталога с этими файлами:

```sh
asset=brain-0.2.0-x86_64-unknown-linux-musl
awk -v name="$asset" '$2 == name {print}' SHA256SUMS > selected.sha256
# Требуется ровно одна запись для выбранного файла.
test "$(wc -l < selected.sha256)" -eq 1 &&
  sha256sum --check selected.sha256 &&
  install -Dm755 "$asset" "$HOME/.local/bin/brain"
```

Для ARM64 значение `asset` — `brain-0.2.0-aarch64-unknown-linux-musl`. При отсутствии записи или несовпадении суммы установку не продолжайте. Файлы и суммы пока не подписаны. Автоматический установщик проверяет выбор суммы строже.

### Из исходников

Нужны версия Rust из `rust-toolchain.toml`, компиляторы C/C++ и зависимости из Cargo.lock:

```sh
git clone --branch v0.2.0 https://github.com/vavavadusik-crypto/brain-ed.git
cd brain-ed
cargo build --locked --release -p brain-cli
mkdir -p "$HOME/.local/bin"
cp "${CARGO_TARGET_DIR:-target}/release/brain" "$HOME/.local/bin/brain"
export PATH="$HOME/.local/bin:$PATH"
```

Это нативная сборка для текущей системы. Требования — в [руководстве](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/INSTALL.md). Веса моделей не включены.

## Первые пять минут

Пять минут — ориентир без компиляции и загрузки моделей.

```sh
brain init
brain init --agents --dry-run
brain init --agents
brain remember "Сборка использует cargo --locked" --kind decision --tag demo
brain --offline ask "Что решили о сборке?" --no-archive
brain ui
```

`init` создаёт или обновляет БД. Проверьте план интеграций перед подтверждением; конфликты могут быть пропущены. Переподключите клиентов после изменений. `remember` сохранит решение; `ask` найдёт свидетельства без облачного ключа. Для точной проверки: `brain --offline recall "cargo locked"`. `ui` открывает или печатает loopback-адрес настроек; при необходимости откройте его вручную. `brain doctor` показывает настройки и наблюдавшийся захват. Запись конфигурации не доказывает рабочий MCP: см. [интеграции](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/INSTALL.md#connecting-agents-claude-code-codex-cursor) и [профили клиентов](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/client-profiles.md), включая Hermes.

Семантическая модель загружается отдельно через `brain model install`. `--offline` запрещает загрузку моделей, но не явно запрошенные LLM/сетевые вызовы.

## Сценарии использования

### Общая память агентов

Сохраните решение с причиной, ошибку с попытками исправления или план со статусом. Другой помощник найдёт это через MCP, вместе с источником. Пространства и происхождение данных помогают сохранять границы. Brain не заставляет агента обращаться к памяти и не делает каждое сохранённое утверждение истинным.

### Журнал и поиск прошлых сессий

Архив включается отдельно. Сначала проверьте источники и приватность:

```sh
brain archive enable --since-days 7
brain archive collect
brain archive status
brain archive search "ошибка сборки" --limit 5
```

Коллектор читает поддерживаемые локальные файлы сессий, маскирует распознанные секреты и сохраняет приватный поисковый архив. `ask` и MCP `memory_search` могут добавлять ограниченные выдержки из него. В CLI `--no-archive` исключает архив из ответа. Даты и фильтры ролей сужают поиск. Покрытие зависит от доступных файлов и форматов клиента: ориентируйтесь на status, а не на предположение о полной истории. См. [журнал](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/journal.md) и [архив](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/session-archive.md).

### Дистилляция решений, ошибок и тупиков

Дистиллятор читает уже сохранённый маскированный архив и записывает проверенные структурированные факты в граф памяти. Провайдер настраивается отдельно. Есть три пути:

- **Локальная модель:** собственный OpenAI-совместимый сервер на loopback. Brain его не устанавливает и не запускает; выбранный текст остаётся на машине при локальной конфигурации сервера.
- **Подписка Claude Code:** встроенный CLI-адаптер использует уже установленный и авторизованный клиент. Доступность модели и лимиты зависят от подписки; у Claude-адаптера отключены инструменты. Есть и адаптер подписки Codex со своими ограничениями.
- **API:** OpenAI-совместимый HTTPS endpoint, ключ через имя переменной окружения. Выбранный текст уходит провайдеру по его условиям; возможна отдельная оплата API.

Для настроенного локального сервера:

```sh
brain llm add local --base-url http://127.0.0.1:8080 --model local-model --context-tokens 16384
brain distill run --provider local --dry-run --max-sessions 5
# После проверки плана — реальный вызов локального провайдера:
brain distill run --provider local --max-sessions 5
```

Альтернатива через уже авторизованный Claude Code:

```sh
brain llm add subscription --command claude --model sonnet --effort medium --context-tokens 128000 --timeout-seconds 900
brain distill run --provider subscription --dry-run --max-sessions 5
brain distill run --provider subscription --max-sessions 5
```

Предварительный просмотр не вызывает модель и не пишет факты. Реальные запуски показывают отклонения и сохраняют прогресс. Валидация проверяет согласованность свидетельств, не истинность выводов. См. [руководство](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/distill-guide.ru.md) и [провайдеры/API](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/distiller.md).

### Командный режим для компании

Начните с демо на синтетических данных из checkout исходников:

```sh
tools/team-demo.sh
tools/team-demo.sh --via-relay
```

Это реальные локальные процессы в раздельных временных HOME, не проверка физического парка машин. Перед пилотом прочитайте [подключение команды](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/team-mode.ru.md), [публикацию и вопросы руководителя](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/team-mode-facts.md), [настройку relay](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/relay.md).

Манифест явно выбирает проекты, пространства, получателей и классы/поля. Руководитель спрашивает помощника: «Какие ошибки открыты?» или «Какие решения приняли?». `team_ask` читает указанные настроенные машины; `team_manifest` и `team_peers` показывают политику и свежесть. Включить публикацию через эти инструменты нельзя.

Ответ показывает источник, время, давность и покрытие; недоступная машина — пробел. Передаются разрешённые сводки, задачи и недавние метаданные Git. Командная схема никогда не передаёт сырые чаты, вывод инструментов, файлы, пути, diff и автора/email Git. Одобренная сводка всё же может содержать приватный текст. Наблюдения за экраном и произвольными файлами нет.

## Безопасность и приватность

Хранение и поиск по умолчанию локальны, автоматической телеметрии нет. Явно выбранная облачная/API или подписочная дистилляция отправляет маскированный текст провайдеру; для локальной обработки выбирайте loopback-сервер.

При записи и поддерживаемом импорте маскируются известные форматы секретов. Неизвестные форматы и обычные личные сведения могут сохраниться. Маскировка не разрешает публиковать архив. Текст архива, ответы модели и командные факты — **недоверенные данные**, а не системные инструкции. Происхождение помогает проверить утверждение, но не удостоверяет его.

Архив принадлежит локальному владельцу и не имеет проектных ACL. Разрешение на командные факты нельзя переносить на сырые разговоры. TLS и дайджесты защищают настроенный транспорт и целостность; подписей автора Ed25519 у срезов пока нет. Текущие credentials не являются Biscuit-токенами. Relay переносит вложенный TLS и не сохраняет содержимое потоков; оператор отвечает за хост, доступность и журналы службы.

## Известные ограничения 0.2.0

- Предварительная Linux-версия. ARM/Termux не означает совместимость с любым телефоном. macOS/Windows требуют переноса безопасной работы с файлами, прав, расписаний, упаковки и CI; одной смены target недостаточно.
- [Аудит релиза](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/docs/release-audit-0.2.md) описывает локальные синтетические тесты и проверенный экспорт исходников. Новые musl-бинарники, удалённый GitHub CI и публикация в этот прогон не входили. Проверка загрузки README использовала локальную подстановку. Это отдельные проверки перед выпуском.
- Нет формального доказательства безопасности или независимого аудита; не заявлена готовность к enterprise/fleet, публичному NAT и длительной работе распределённого парка.
- Захват частичный, записи ролей, поиск и визуализация ограничены. История может быть неизвестна. Источники среза имеют отдельные watermarks, общей одновременной картины нет. В срезе максимум 24 сущности, в Git-источнике — до восьми недавних коммитов.
- Командный режим не возвращает сырые данные при сбое дистилляции. Отзыв политики прекращает будущую разрешённую выдачу, но не стирает уже скопированное получателем. Метка помощника не удостоверяет человека за ним.
- Таймеры используют systemd user. Наличие unit-файла не доказывает успешный запуск; в Termux без systemd нужен подходящий ручной процесс. Качество модели, контекст и лимиты подписки влияют на дистилляцию.
- Бинарники не подписаны; побитовая воспроизводимость независимых сборок не установлена. При обновлении переподключите клиентов, использующих старый MCP-процесс. Сохраняйте бэкапы: в версиях `0.x` форматы и интерфейсы могут меняться.

## План развития

Ближайший этап — контролируемый пилот в компании, повторяемые проверки GitHub CI и релизов, подготовка установки на парк машин и удобные локальные/API-сценарии дистилляции. Далее — macOS перед Windows, подписи срезов и ограниченное делегирование доступа, поиск на исходной машине и веб/мобильная панель руководителя. P2P и обход NAT требуют проверки на реальных сетях. Это намерения без обещанных дат, не возможности 0.2.0: [полный ROADMAP](https://github.com/vavavadusik-crypto/brain-ed/blob/v0.2.0/ROADMAP.ru.md).
