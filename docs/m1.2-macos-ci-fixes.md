# M1.2: оставшиеся падения distill_process на macOS

Дата: 2026-10-27. Worktree/ветка: `m1-macos`.
Перед изменениями выполнено `git merge e7-next`: fast-forward с `c722084`
на `4335d11`. Push не выполнялся.

## Точные причины по второму CI

Источник: локальный `_runs/macos-ci/run-40560447405.log` в родительском
каталоге worktrees. В нём **ARM64: 35 passed / 14 failed** (строка 665),
**Intel: 33 passed / 16 failed** (строка 1345). Архитектуры в исходном брифе
были переставлены. В этом CI на каждой архитектуре выполнялись 49 тестов;
Linux включает дополнительные systemd-тесты.

### 14 общих падений: проверка окружения внутри Python-фейка

Строка 552, ARM64, scheduled provider:

```text
synthetic CLI failure metadata: {"phase": "environment", "exception": "AssertionError", "line": 17, "unexpected_env_keys": ["__CF_USER_TEXT_ENCODING"]}
```

Та же причина у subscription-тестов: строки 558, 567 и далее на ARM64,
1229, 1235 и далее на Intel. Даже отдельный preflight с `env_clear()`,
который вообще не запускает продуктовый адаптер, падает на этом ключе:
строки 640 и 1318. Следовательно, Python уже успешно запущен, а дополнительный
ключ появляется в окружении дочернего runtime после очистки родителем.
`command failed (exit 1)` — следствие assertion фейка до обработки argv/stdin.
Этот лог не указывает на сбой shebang, PATH или executable trust.

`__CF_USER_TEXT_ENCODING` известен Apple CoreFoundation: он перечислен
в `__CFEnv`, а инициализация вызывает `__CFStringGetUserDefaultEncoding`
с комментарием о раннем `setenv` ([исходник Apple, CFRuntime.c](https://github.com/apple-oss-distributions/CF/blob/main/CFRuntime.c#L788)).
Это согласуется с наблюдаемой добавкой Darwin runtime. Конкретный стек
инициализации Python на runner в логе не записан.

### Два дополнительных падения Intel: совпадение временных каталогов

Строка 1220, `a_limited_subscription_hands_over_to_the_next_provider`:

```text
SqliteFailure(Error { code: Unknown, extended_code: 1 }, Some("table archive_meta already exists"))
```

Строка 1226, `batches_respect_fifty_sessions_real_escaped_bytes_and_large_session_isolation`:

```text
SqliteFailure(Error { code: CannotOpen, extended_code: 14 }, Some("unable to open database file: /private/tmp/brain-ci.NeoMdB/brain-distill-16743-1793126298736692000/.brain/archive/sessions.sqlite"))
```

Сбой происходит в `Fixture::new` / `Fixture::archive`, до запуска провайдера.
Общий helper строил путь только из tag, PID и `SystemTime::now().as_nanos()`.
Единица представления nanoseconds не гарантирует уникальности показаний часов:
при одном timestamp параллельные тесты получали один HOME/SQLite, а thread-local
cleanup одного теста мог удалить каталог другого. `create_dir_all` молча
принимал уже существующий каталог. Это объясняет и существующую таблицу, и
последующее исчезновение базы. Идентичный timestamp воспроизводит коллизию
детерминированно на Linux; изменение `/var` alias к этой причине не требуется.

## Исправления и защита от регрессии

- Только тестовый Python-фейк разрешает ровно `__CF_USER_TEXT_ENCODING` при
  `sys.platform == 'darwin'`. Продуктовый `env_clear` и его точный allowlist
  не изменены. Абсолютный путь Python, найденный до ограничения PATH в M1.1,
  сохранён. Нет wildcard-исключения для `__CF_*`.
- Новая регрессия моделирует Darwin и появление этого ключа внутри отдельного
  fake-процесса на Linux. Чистый preflight проходит; `BRAIN_SECRET`,
  `OPENAI_API_KEY` и посторонний `__CF_OTHER` отвергаются. Диагностика содержит
  только имена/фазу и не раскрывает синтетические значения.
- Общий test helper добавляет к PID/timestamp process-wide `AtomicU64` sequence
  с `Ordering::Relaxed`. Для уникальности нужен атомарный increment, а не
  синхронизация данных. Канонизация только родителя и thread-local cleanup
  сохранены. Регрессия принудительно задаёт одинаковое время 32 потокам,
  проверяет разные имена, затем проверяет, что cleanup одного потока не удаляет
  данные другой фикстуры.
- Контроль без Darwin-исключения воспроизводит exit 1 с тем же именем ключа;
  исправленный fake даёт exit 0. В отдельной копии helper без sequence-суффикса
  32 потока дают один путь и exit 101; исправленная копия даёт 32 пути и exit 0.
  Эти контроли не изменяли исходники или собранный продукт.

Изменения Rust ограничены `brain-cli/tests`. Проверки executable trust,
приватных каталогов, hooks/tools/MCP/sandbox, лимитов, размера ответа, timeout,
маскирования и курсора не ослаблены. Пользовательский `~/.brain` не открывался
командами проверок; они используют временные синтетические HOME и loopback fake.

Первый полный прогон с обычным числом тестовых потоков остановился на
`subscription_timeout_kills_descendant_group`: мгновенная проверка `/proc`
ещё не увидела отсутствие/Z-состояние потомка. Обе новые регрессии в этом
прогоне прошли. Изолированный повтор timeout-теста прошёл (1.08 s).
Продукт отправляет SIGKILL группе и ожидает непосредственного ребёнка;
завершение потомка наблюдается отдельно. Наблюдение согласуется с гонкой
мгновенной проверки после сигнала, но состояние неудачного процесса в лог
не записано. Timeout-тест и продуктовый код не изменялись. Окончательный
полный прогон использует `-- --test-threads=4`, чтобы ограничить параллелизм
на общей машине; это тот же набор тестов и assertions.

Новый native macOS CI в этой сессии не запускался: push не выполнялся.
Linux-воспроизведение и исправление тестовых причин не заменяют повторный CI
на обеих архитектурах Darwin. Статус поддержки платформ в продуктовых
документах не изменён.
