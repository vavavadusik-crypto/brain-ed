## Наблюдения из первого прогона

Источник: локальный `run-40512447639.log`, обе архитектуры GitHub macOS CI.

- ARM64: в `keep_raw_is_opt_in_private_and_refuses_symlinks` loopback fake
  падает на `stream.read(...).unwrap()` с `WouldBlock`, errno 35.
  Клиент сообщает transport error. Затем `Server::drop` повторно паникует
  на `join().unwrap()` во время unwind: весь `distill_process` завершается
  `SIGABRT`, поэтому остальные падения этой архитектуры не перечислены.
- Intel: `distill_process` — 32 passed, 13 failed. У командных адаптеров
  наблюдается `command failed (exit 1)`, а не отказ проверки executable trust.
  В числе падений — успех Claude/Codex, event-list, atomic output replacement,
  safe install symlink, лимиты, size cap, timeout, unsupported flag и
  `scheduled_provider_limit_exits_quietly_once_and_next_tick_resumes`.
- На Intel `keep_raw_is_opt_in_private_and_refuses_symlinks` проходит.
  Лог не подтверждает, что причиной этих падений были staff/admin,
  `/etc/group`, алиасы temp-каталогов или `ps`.

## Исправления и регрессии

1. Принятый TCP stream явно переводится в blocking mode до установки read
   timeout и чтения HTTP-запроса. Это устраняет зависимость от наследования
   nonblocking flag слушателя на BSD. Существующие framing, timeout и loopback
   binding сохранены. Регрессия принудительно включает nonblocking на принятом
   stream и отправляет JSON частями. Она проходит на Linux; изолированный
   контроль с удалённой строкой `set_nonblocking(false)` воспроизводит
   `WouldBlock` и завершается с кодом 101.
2. Очистка fake-сервера сохраняет исходный panic теста. Ошибка worker thread
   продолжает проваливать тест при обычном Drop, а во время уже начатого unwind
   не вызывает второй panic/abort. Регрессия одновременно создаёт обе ошибки
   и проверяет, что наружу возвращается именно исходная.
3. Fake Claude/Codex больше не привязан к `#!/usr/bin/python3`.
   До ограничения PATH определяется абсолютный `sys.executable` доступного
   Python, затем используется прямой shebang. Это убирает зависимость от
   системного launcher и его выбора runtime. На Linux прежний сценарий с
   env_clear и PATH, содержащим только fake CLIs, проходит.
   **Сам лог Intel не позволяет доказать, какая именно проверка Python падала.**
   Нативное подтверждение этой гипотезы остаётся задачей следующего CI.
4. Для недоказанной причины добавлена диагностика только в fake-скрипт:
   `fake-failure.json` содержит фазу (`startup`, `environment`, `cwd`, `argv`,
   `stdin`), класс исключения, номер строки и имена неожиданных env-переменных.
   Rust fixture выводит эти метаданные в захваченный test output при ошибке
   fake, в том числе для scheduled entrypoint. Значения env, argv, prompt и
   traceback туда не записываются. Регрессия проверяет чистый preflight,
   отказ при посторонней переменной и отсутствие её значения в диагностике.
5. Общий helper интеграционных тестов канонизирует только уже существующий
   корень temp-каталогов до добавления имени фикстуры. Это делает локальные
   тесты независимыми от Darwin `/var` → `/private/var` и `/tmp` aliases,
   даже вне настройки TMPDIR в CI. Регрессия создаёт такой алиас на Linux,
   проверяет канонический родитель и сохранение симлинка внутри фикстуры.
   Продуктовая проверка `--keep-raw` по directory descriptors не изменена.

## Почему защита не ослаблена

- На Darwin `group_is_private` остаётся fail-closed. Принадлежность владельца
  к основной группе сама по себе не доказывает отсутствие других участников;
  общая staff не становится доверенной для записи.
- Проверки владельца, group/world write, executable mode, safe install symlink
  и root-owned sticky ancestor не изменены. Никаких дополнительных исключений
  для исполняемых файлов или домашних каталогов нет.
- Окружение продукта по-прежнему очищается и собирается по прежнему allowlist.
  Fake сохраняет все прежние проверки env, stdin, пустого приватного cwd,
  отключённых hooks/MCP/tools и read-only sandbox. Новых разрешённых env keys нет.
- Product stdout/stderr адаптеров по-прежнему приватны: ошибки fake доступны
  через отдельную тестовую фикстуру, а не через раскрытие вывода реальных CLI.
- Существующие проверки отказа записи через симлинк и публичный raw directory,
  bounded response, timeout/process-group cleanup, masking и курсора сохранены.
- Локальные проверки используют синтетические HOME и loopback fake. Не
  устанавливались SDK, модели, targets или новые зависимости. Команды Cargo
  выполнялись offline, с `CARGO_BUILD_JOBS=4`, `nice -n 10` и
  `CARGO_TARGET_DIR=$HOME/projects/brain-ed-target/CX-M1`.
