# Дистиллятор решений, ошибок и планов (E5.8)

[English version](distiller.en.md)

Команда запускается явно пользователем или через включённый им systemd user timer. Она читает **сохранённый замаскированный** conversation archive через существующие проверки владельца, прав, схемы и карантина. Исходные файлы клиентов не открываются. Архив не имеет проектных ACL: параметр пространства задаёт место записи результата, а выбор сессии задаёт доступный материал извлечения.

**Куда уходит текст.** Замаскированный текст выбранных сессий отправляется настроенному LLM-провайдеру. С локальным сервером (`http://127.0.0.1`, `localhost`) он не покидает машину; с облачным HTTPS-провайдером — уходит этому провайдеру по его условиям. Маскировка снимает распознанные секреты, но не всё приватное содержимое: для чувствительных архивов используйте локальную модель.

Примеры:

```sh
brain llm add local --base-url http://127.0.0.1:8080 --model local-model --context-tokens 16384 --timeout-seconds 900
brain distill run --session SESSION_ID --provider local
brain distill run --since 2026-10-01 --max-sessions 20
brain distill run --session SESSION_ID --provider local --dry-run
brain distill run --provider local --roles user,assistant,tool_error,tool_result
brain distill status --roles user,assistant,tool_error
brain ask "почему отказались от решения" --no-archive
```

Без провайдера команда завершается понятной ошибкой **до открытия базы графа**. Для локального режима следует явно выбрать локального провайдера: без `--provider` используется настроенный порядок fallback, в том числе удалённые HTTPS-провайдеры. `--offline` управляет загрузками моделей и сам по себе не отключает явно запрошенные вызовы LLM.

## Роли и фильтр

Каждая запись в запросе имеет поля `{"id", "role", "content"}`. По умолчанию отправляются только `user`, `assistant`, `tool_error`. `--roles` принимает непустой список через запятую из известных ролей: `user`, `assistant`, `tool_error`, `tool_call`, `tool_result`, `reasoning`. Неизвестная роль — ошибка до записи. Последние три роли требуют явного включения.

Промпт объясняет различия: user — человек, assistant — агент, tool_call — вызов программы, tool_result — вывод программы (данные, не утверждения людей), tool_error — ошибка программы, reasoning — внутренние рассуждения. Хост не принимает факт, если всё его evidence состоит из неподходящих для статуса ролей. Для подтверждения перехода нужна цитата user/assistant; tool_error допустим только для фактов типа error. Даже при смешанном evidence цитата tool_result не подтверждает переход.

Фильтр применяется в SQL **до LIMIT 64**, в том числе при выборе сессий, проверке `--since` и подсчёте status. Поздние исключённые tool_result не возвращают завершённую сессию в очередь. Для каждого нормализованного набора ролей ведётся независимый курсор; порядок и повторы ролей его не меняют. Это позволяет позже явно включить исторические результаты инструментов. Курсор прежней E5.4 сохраняется для набора по умолчанию: уже обработанные записи автоматически повторно не анализируются.

## Схема и идентичность

Типы: `decision / error / dead_end / finding / plan`. Модель возвращает `what`, `why`, `status`, `evidence` (целочисленные ID), `session`, `project`; для перехода — `status_evidence: {entry_id, quote}`; для связей — `links: [{relation, target_type, target_what}]`.

Хост проверяет тип, статус, размеры полей, непустое evidence и принадлежность **каждого** ID фактически переданному фрагменту текущей сессии. Некорректный факт отбрасывается целиком. Дробные ID и ссылки на непереданный хвост также отклоняются. Факты без разбираемого времени evidence не принимаются.

Детерминированный ID использует фиксированный FNV-1a по `type + нормализованный what + нормализованный project`; нормализация сворачивает пробелы и приводит Unicode к нижнему регистру. При совпадении ID проверяется полная идентичность полей, коллизия вызывает отказ. Project берётся из `cwd` evidence, значение модели игнорируется; разные cwd внутри одного факта отклоняются. Пустой cwd старых архивов образует отдельную идентичность.

Metadata обычного графового узла:

- `distilled_fact: true`, `kind` (тип), `what`, `why`, `status`, `project`;
- `evidence`: объединение ID всех принятых свидетельств;
- `evidence_by_session`: отображение сессий в списки ID;
- `archive_session`: сессия последнего принятого утверждения;
- `when_min / when_max`: диапазон said_at всего принятого evidence.

Любой `when` в ответе модели **игнорируется**, включая числа и строки вне диапазона. Said_at вычисляется общим парсером архива из `ts` (ISO-8601 либо Unix seconds). Первичная `valid_from` — минимум evidence. При смене статуса `valid_from` новой версии — максимум evidence нового утверждения; утверждение старше действующего статуса отклоняется. При добавлении evidence с прежним статусом начало действующей версии сохраняется.

`brain ask` выдаёт факты как обычные поисковые результаты с `kind`, `type` и `status`. Типы decision/error используют соответствующие NodeKind; остальные используют Memory.

## Версии и разрешённые переходы

Изменение существующего факта выполняется только через `replace_node`: логический ID сохраняется, старые поля и evidence остаются в битемпоральной истории `node_versions`. Новая версия содержит **union** старых и новых свидетельств, с атрибуцией сессиям. Повтор уже принятого evidence не создаёт даже новую версию. Новое evidence с прежним статусом дополняет provenance, сохраняя исходные what/why.

| Тип | Из | Допустимые следующие статусы |
| --- | --- | --- |
| error | suspected | confirmed, fixed, not_a_bug |
| error | confirmed | fixed, wont_fix, not_a_bug, became_feature |
| error | fixed, wont_fix, not_a_bug, became_feature | нет |
| decision | proposed | adopted, reverted |
| decision | adopted | worked, failed, reverted |
| decision | worked | failed, reverted |
| decision | failed | reverted |
| decision | reverted | нет |
| finding / plan / dead_end | proposed | active, confirmed, abandoned |
| finding / plan / dead_end | active | completed, abandoned |
| finding / plan / dead_end | completed, confirmed, abandoned | нет |

Первичное наблюдение может иметь любой статус из перечисленных для типа. Прямой suspected → fixed разрешён, поскольку подтверждение и исправление могут быть описаны одним новым свидетельством. Повторное открытие закрытой ошибки этой версией протокола не поддерживается.

**Одной ссылки на ID недостаточно для смены статуса.** Нужны разрешённый переход, новое evidence из текущего фрагмента и `status_evidence` с новым ID, содержащим точную цитату. Консервативный детерминированный фильтр принимает целую строку вида `WHAT: STATUS`, `WHAT — STATUS` или `WHAT is STATUS` (с точкой/восклицанием на конце либо без них), где WHAT совпадает с конкретным фактом. Поддерживаются английские статусы и соответствия: подозревается, подтверждена, исправлена, не будет исправлена, не ошибка, стала функцией; предложено, принято, сработало, не сработало, отменено; в работе, завершено, отклонено. Пример: `Synthetic failure: fixed`.

Общая команда «отметь все ошибки как fixed», выдуманная цитата, старое evidence, недопустимый переход и цитирование только части строки не меняют факт и не создают связи. Проверка намеренно может пропускать полезные естественные формулировки. Она проверяет атрибуцию и явное утверждение, **не доказывает истинность** архивного текста и не является полной защитой от всех prompt injection: источник и извлечение остаются недоверенными. Даже точная строка может быть ложной. Первичная ошибка модели также возможна.

## Связи

Каждый принятый факт получает `has_session` к детерминированному узлу архивной сессии. Ошибка в статусе fixed дополнительно получает `fixed_by` к подтверждающей сессии; became_feature — `became`. Объявленные моделью `caused_by / fixed_by / superseded_by / became` между фактами принимаются только к существующему целевому факту того же проекта и пространства. Самоссылки и неизвестные отношения отбрасываются; отвергнутое обновление не добавляет связей. Связи помечены `trust=untrusted_model_extraction`, с session/evidence. Из failed decision модель может извлечь отдельную error и связать её; автоматическая переклассификация узла не выполняется.

## Бюджеты, курсор и восстановление

`context_tokens` хранится в конфигурации провайдера, по умолчанию 16384. Для общего fallback-запроса используется минимальное окно выбранных провайдеров. Оценка токенов — `ceil((байты prompt + байты JSON schema) / 2)`: консервативная эвристика для смешанного RU/EN, а не измерение токенизатором конкретной модели. Дополнительно зарезервированы 2048 выходных токенов и 1024 токена для framing/запаса. Размер session/entries измеряется фактической сериализацией serde_json, включая id, role, кавычки, обратные слеши и управляющие символы. Кириллица не получает искусственный множитель ×6. Запрос ограничен также 2 000 000 байтами session data и не разрывает UTF-8 символ. Малое окно вызывает явный отказ. Проверка гарантирует соблюдение этой оценки окна; фактическое число токенов зависит от модели. Шаблонам передаётся `chat_template_kwargs.enable_thinking=false`; соблюдение этой опции зависит от сервера. JSON schema передаётся через OpenAI-compatible response_format и проверяется повторно хостом.

Сессии читаются порциями до 64 записей, запросы содержат фрагменты нескольких записей. Даже одна большая запись разбивается без потери хвоста. Evidence разрешено только из текущего отправленного фрагмента. Курсор двигается лишь после обработки всей записи. После сбоя посередине большой записи её фрагменты могут отправиться повторно; принятие фактов идемпотентно.

Отдельная таблица `distill_progress(space_id, session_id, last_entry_id, completed_at)` отмечает полностью обработанные записи. Таблица distill_runs из WIP не используется. Завершённые сессии пропускаются, новые append-записи выбранных ролей возвращают их в очередь. Для дополнительных наборов ролей используется таблица `distill_filter_progress`, изолированная по space/session/role_filter. `--max-sessions` ограничивает число реально обрабатываемых сессий; `--since` выбирает сессии по наличию видимого evidence в периоде, после чего обрабатывается вся выбранная сессия. Неверная дата — ошибка. Архивные изменения/снятие карантина позади курсора не запускают автоматический повторный анализ.

Записи графа завершаются до курсора. При частичной ошибке уже принятые факты сохраняются, незавершённый фрагмент повторяется без удвоения узлов/версий. Процессный файловый lock рядом с выбранной базой сериализует дистилляторы; другие команды Brain не блокируются этим lock. Граф и курсор не являются одной общей транзакцией.

`distill status` читает базу без записи и считает завершённые/оставшиеся **видимые сейчас** сессии относительно текущего пространства, а также действующие факты по type/status. Отсутствующий архив даёт нулевую очередь. Отчёты команд не печатают текст архива или ответы модели. Защита E5.3 (разбор URL, запрет userinfo, pin localhost, отсутствие редиректов и безопасные транспортные ошибки) сохраняется.


## Таймаут и прогресс

`brain llm add ... --timeout-seconds 900` сохраняет `timeout_seconds` у провайдера. По умолчанию 120 секунд, допустимо 10..=3600; старые settings без поля получают 120. При fallback каждый провайдер использует собственный таймаут. У `brain llm test --timeout-seconds ...` остаётся явный override для диагностики. Таймаут охватывает запрос и чтение ответа; ошибка не выводит URL, ключ, архивный текст или ответ модели. Для медленной CPU-модели пример выше задаёт 900 секунд. Если и этого мало, увеличьте таймаут либо уменьшите context_tokens.

На каждый кусок stderr получает строку `state=started`, затем строку `state=finished` или `state=failed`: число сессий в запросе и порядковый номер вызова, байты сериализованных session data, прошедшие секунды и число записанных фактов (`accepted`). ID/названия сессий, текст архива и ответы модели в прогресс не попадают. После ошибки курсор не перескакивает через неуспешный кусок; успешно обработанные предыдущие куски сохраняют прогресс.

`--dry-run` читает выбранный поток и существующий курсор, рассчитывает те же куски и возвращает `sessions`, `chunks`, `calls`, `bytes`, `roles`, `facts_written=0`. Здесь `bytes` — сумма сериализованных session data, без постоянного системного промпта, JSON schema и HTTP framing. Команда ничего не отправляет провайдеру и не создаёт/изменяет граф, атрибуцию, таблицы прогресса или lock-файл. Провайдер всё равно должен быть настроен: его окно определяет бюджет. Ограничения session/since/max-sessions и текущие курсоры действуют так же, как при обычном запуске.

## Синтетическое сравнение

`tools/distill_synthetic_benchmark.py BEFORE_BINARY AFTER_BINARY` запускает оба бинарника с отдельными временными HOME и loopback HTTP-стендом без модели. Стенд возвращает пустой список фактов; печатаются только счётчики. Сессия: 30 чередующихся user/assistant по 640 UTF-8 байт и 100 tool_result по 4096 байт, окно 16384. Данные не берутся из пользовательского архива. Для изоляции временных файлов задавайте TMPDIR внутри своего target.

| --- | ---: | ---: |

Дополнительные process-тесты проверяют допустимость evidence/status на синтетических ответах; реальный архив и модель для проверки не используются.

## Диагностика отказов (E5.6)

Итоговый JSON `distill run` содержит `proposed`, `accepted`, `rejected` — объект
`{reason: count}` без содержимого фактов. `facts_written` остаётся совместимым
синонимом `accepted`. Для каждого успешно обработанного куска и всего запуска:
`proposed = accepted + sum(rejected.values())`. В stderr эти же поля добавлены
к строкам прогресса; `state=started` содержит нули. `--dry-run` также возвращает
нули. Accepted включает новые факты и принятые обновления provenance/статуса.
На каждый факт считается только первая обнаруженная причина; ошибки хранилища
и провайдера по-прежнему завершают команду ошибкой и не продвигают курсор куска.

| Причина | Значение |
| --- | --- |
| unknown_type | Неизвестный тип |
| invalid_fields | Отсутствующее поле или неверный тип обязательного строкового поля |
| empty_what | Пустой what после свёртки пробелов |
| field_too_long | what > 2000 или why > 8000 UTF-8 байт |
| unknown_status | Статус не допускается для выбранного типа |
| session_mismatch | Session отсутствует в переданном пакете |
| no_evidence | Нет непустого массива evidence |
| invalid_evidence | ID evidence не представим целым i64 |
| evidence_outside_chunk | Хотя бы один ID не передан в текущем фрагменте указанной session |
| tool_result_only | Нет evidence от user/assistant или tool_error для error |
| mixed_projects | Evidence относится к разным cwd |
| invalid_timestamp | Время хотя бы одного evidence не разбирается |
| transition_not_allowed | Переход отсутствует в таблице переходов |
| transition_unsupported | Нет нового evidence и точной новой цитаты допустимой роли |
| stale_transition | Новое утверждение старше valid_from действующего статуса |
| duplicate | Тот же статус и нет нового evidence |
| over_max_facts | Элемент после первых 100 в ответе куска |

Структурно неверный JSON (например, отсутствующее обязательное поле) может
быть отклонён транспортной проверкой ещё до счётчиков фактов; это ошибка
провайдера, а не успешный кусок с отказами. Enum передаётся провайдеру для
ограничения grammar; хост независимо проверяет допустимость type/status.

Prompt и enum type/status строятся из тех же таблиц, что разбор.
Канонические типы имеют русские синонимы: decision — решение, error — ошибка,
dead_end — тупик, finding — находка, plan — план. Перечисленные выше русские
эквиваленты статусов принимаются и в поле status, нормализуясь к английскому.
Для первичного факта status_evidence необязателен; для смены статуса обязателен.
JSON имеет форму `{"facts":[...]}`; обязательные поля каждого факта:
`type`, непустой `what`, `why`, `status`, непустой `evidence`, точный `session`,
`project` (последний хост заменяет значением из cwd).

### Локальное сохранение ответа

`brain distill run --keep-raw /local/private/distill-debug` сохраняет текст
ответа выбранного провайдера для каждого куска в отдельном новом файле.
**Файл содержит производное от архива, только для локальной отладки.**
Не добавляйте такие файлы в git, отчёты или логи. Без флага ответы не сохраняются.
Сохраняется message content выбранного провайдера, без HTTP-заголовков и ключей;
отклонённые транспортом попытки fallback не сохраняются.

Родитель каталога должен существовать. Конечный каталог создаётся с 0700;
существующий допускается только при владельце текущего процесса и правах 0700.
Любой симлинк в пути и `..` запрещены. Файлы создаются через create-new
(O_EXCL/O_NOFOLLOW) с 0600, никогда не перезаписываются. Необычный umask может
дополнительно сузить права. Ошибка сохранения останавливает кусок до записи
фактов и продвижения курсора. При `--dry-run` каталог и файлы не создаются.

API-ключа. Brain запускает только встроенные адаптеры `claude` и `codex`, без
shell и произвольных команд. Авторизация и доступность модели зависят от вашей
подписки и версии клиента. Само добавление провайдера не запускает CLI.

```bash
brain llm add subscription --command claude --model sonnet --effort medium \
  --context-tokens 128000 --timeout-seconds 900
brain distill run --provider subscription --dry-run --max-sessions 10
brain distill run --provider subscription --max-sessions 10
```

Плановый запуск включается отдельно командой `brain distill schedule enable`
(см. ниже). Brain не устанавливает расписание автоматически. Повторный запуск
продолжает с сохранённых курсоров. При распознанном лимите подписки возвращается
JSON `status: "provider_limited"` с кодом завершения 0: курсоры текущего пакета
не сдвинуты, предыдущие успешные запросы сохраняют прогресс. Плановый запуск
сохраняет этот результат для `schedule status`, не печатает прогресс в stderr
и не повторяет запрос в цикле. Неизвестная ошибка клиента остаётся ошибкой;
распознавание лимитов опирается на фиксированные английские категории клиента,
а не гарантированный единый протокол всех версий.

**Для недоверенного архива рекомендуется Claude.** Он запускается с `-p`,
`--output-format json`, `--json-schema`, `--tools ""`, `--strict-mcp-config`,
пустым `--mcp-config '{"mcpServers":{}}'` и `--no-session-persistence`.
Ответ берётся только из объекта `structured_output`; текстовое `result` не
принимается как факт. Если версия клиента не принимает защитный флаг, запуск
завершается отказом; повторной попытки с инструментами нет. Опциональные model
и effort передаются отдельными аргументами. Формат и флаги сверены с
[CLI reference Claude Code](https://code.claude.com/docs/en/cli-reference) и
[программным запуском](https://code.claude.com/docs/en/headless); реальная
совместимость установленного клиента требует отдельного прогона владельцем.

Альтернатива:

```bash
brain llm add subscription-codex --command codex --model YOUR_MODEL --effort low
brain distill run --provider subscription-codex --dry-run --max-sessions 5
brain distill run --provider subscription-codex --max-sessions 5
```

Codex использует `exec --skip-git-repo-check --ephemeral --sandbox read-only`,
`--output-schema`, `-o` и stdin `-`, а effort передаётся через
`-c model_reasoning_effort=...`. Модель можно опустить, чтобы использовать
настройки клиента. У Codex нет режима «без инструментов»: пустой cwd и sandbox
read-only ограничивают запись, но не гарантируют изоляцию чтения домашнего
каталога, пользовательских конфигураций или подключённых MCP. Это более слабая
граница для prompt injection из архива. Не подключайте к такому клиенту
привилегированные интеграции; используйте отдельный профиль/учётную запись ОС,
если нужна более сильная изоляция. См.
[официальный справочник Codex CLI](https://learn.chatgpt.com/docs/cli/reference).

Каждый вызов получает новый пустой cwd 0700. Схема и результат Codex находятся
в соседнем приватном каталоге, файлы 0600; после завершения каталог удаляется.
Промпт передаётся только в stdin, без текста архива в argv. Окружение очищается
до точного списка `PATH`, `HOME`, `LANG`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`;
API-ключи, Brain env, SSH agent и произвольные переменные клиента не наследуются.
Клиент сохраняет доступ к своему профилю через HOME/каталог конфигурации;
очистка env не изолирует файлы и не запрещает загрузку пользовательских hooks.
Приватность облачного провайдера и расход подписки остаются ответственностью
владельца. `--no-session-persistence`/`--ephemeral` не обещают отсутствие всех
логов или удалённого хранения у поставщика.

Исполняемый файл ищется только в абсолютных каталогах PATH. Требуется обычный
исполняемый файл текущего владельца или root без записи для группы/остальных;
симлинки отклоняются, включая npm-shim симлинки. Для такой установки укажите в
PATH каталог с обычным доверенным исполняемым файлом клиента. Произвольная
строка shell в `--command` запрещена. Это проверка файла перед запуском, а не
защита от враждебного процесса того же пользователя, меняющего PATH/файлы.

stdout/stderr клиента не печатаются: диагностика содержит категорию и код
выхода. Каждый поток и результат ограничены 4 МиБ; превышение и таймаут убивают
процесс-группу. Ответ проходит прежние проверки формы, evidence внутри куска,
ролей, проекта, переходов и точных цитат. Перед записью what/why дополнительно
обрабатываются `mask_secrets`. Это эвристическая маскировка известных форматов,
а не доказательство отсутствия любых секретов. `--keep-raw` сохраняет исходный
результат **до** этой маскировки и требует прежней осторожности.

Окно command-провайдеров по умолчанию 128000 токенов; HTTP-провайдеров — 16384.
`--context-tokens` задаёт бюджет, а не меняет возможности модели или её тариф.
`--dry-run --provider NAME` показывает число запросов (`calls`, также `chunks`)
с пакетированием и текущими курсорами. Это число спланированных запросов;
при fallback один такой запрос может потребовать нескольких попыток разных
провайдеров. Фактический расход подписки зависит от
версии CLI, модели, schema/output, ролей, размеров записей и ответа. CLI добавляет
собственные накладные расходы; число вызовов служит измеримым показателем,
но не даёт точного числа токенов или стоимости. Реальный архив и подписка
в проверках E5.8 не использовались.

## Пакеты сессий (E5.8)

По умолчанию дистиллятор объединяет соседние в очереди небольшие сессии, пока
фактический сериализованный JSON помещается в бюджет провайдера. Максимум —
50 сессий на запрос; `--batch-sessions N` позволяет выбрать от 1 до 50.
`--batch-sessions 1` возвращает режим одной сессии на запрос, без объединения.
Оставшиеся после курсора записи небольшой сессии передаются целиком, даже
если при чтении они занимали несколько страниц по 64 записи. Большая сессия,
которая целиком не помещается, обрабатывается одна, по кускам; смешивания её
кусков с другими сессиями нет.

Форма данных в запросе:

```json
{"sessions":[{"session":"session-a","entries":[{"id":1,"role":"assistant","content":"..."}]},{"session":"session-b","entries":[{"id":2,"role":"user","content":"..."}]}]}
```

Каждый факт обязан указать точную `session` из пакета. Неизвестная сессия даёт
`session_mismatch`; evidence другой сессии (даже присутствующей в том же пакете)
или непереданный ID — `evidence_outside_chunk`. Проект и время вычисляются
по evidence этой сессии. Формат ответа `{"facts":[...]}` остаётся прежним.

Все записи фактов и связей пакета должны успешно завершиться до продвижения
любого его курсора. Затем курсоры сессий сохраняются **одной SQLite транзакцией**.
Ошибка посередине записи не помечает ни одну сессию пакета завершённой;
уже записанные факты могут остаться в графе и безопасно дополняются при повторе.
Общей транзакции между графом и курсорами по-прежнему нет.

По умолчанию сначала обрабатываются сессии с самым свежим разбираемым временем
видимой записи выбранных ролей. ISO-8601 и Unix seconds сравниваются после
разбора, а не как строки; при равном времени порядок задаёт ID сессии.
Сессии без разбираемого времени идут последними. `--oldest-first` разворачивает
этот порядок (включая положение сессий с неизвестным временем).
`--max-sessions` по-прежнему ограничивает сессии, а не вызовы.

```sh
brain distill run --provider subscription --max-sessions 100 --dry-run
brain distill run --provider subscription --max-sessions 100 --batch-sessions 10
brain distill run --provider subscription --batch-sessions 1 --oldest-first
```

## Плановое выполнение (E5.8)

```sh
brain distill schedule enable --provider subscription --every 1h --max-sessions 20 --quiet-hours 09-23
brain distill schedule status
brain distill schedule disable
```

Это Linux systemd user timer: `brain-distill.service` и `brain-distill.timer`
в `~/.config/systemd/user`. Используются те же приватная атомарная запись units,
проверки аргументов `ExecStart` и порядок `systemctl --user`, что у архивного
таймера: запись → daemon-reload → enable --now; при отключении сначала
`disable --now`, затем удаление units и daemon-reload. Существующие данные
и курсоры не удаляются. Отказ systemctl возвращает
`files_written_systemctl_failed`, а не сообщение об успешном включении.

Провайдер обязателен и должен быть уже настроен. Интервал по умолчанию `1h`;
принимаются положительное целое число (до 10000) и суффикс `s`, `m`, `h`, `d`.
Максимум сессий по умолчанию 20, допустимый диапазон 1–1000. В unit закрепляются
текущий абсолютный путь бинарника, база и пространство; используется `--offline`.
PATH и доступ к профилю CLI должны быть доступны пользовательскому systemd manager.
После переноса бинарника включите расписание заново. Для работы при отсутствии
пользовательской сессии нужна соответствующая настройка systemd владельцем;
команда её не меняет.

`--quiet-hours 09-23` запрещает запуск с 09:00 включительно до 23:00
исключительно по **локальным часам машины**. Поддерживается ночное окно
`23-09`; `00-24` запрещает запуск весь день. Если флаг не указан, ограничений
по времени суток нет. Проверка выполняется до чтения архива, открытия графа,
lock и вызова провайдера. Уже начатый проход при входе в quiet-hours не прерывается.

Каждый тик делает один ограниченный проход с существующим lock. Таймер ждёт
окончания запуска, затем интервал `OnUnitInactiveSec`; циклических повторов
при лимите нет. Следующий тик продолжит очередь. `schedule status` показывает
наличие units, `enabled`/`active` от systemctl и последний результат из
`~/.brain/distill-schedule-status.json`: `quiet_hours`, `provider_limited`,
`ok` либо `failed`. Файл приватный, содержит время и счётчики, без архивного
текста, ответа провайдера или ключей. Плановый запуск подавляет строки прогресса;
JSON результата сохраняется в stdout для системного журнала.

## Расход вызовов: синтетический архив E5.8

Воспроизводимый запуск с двумя собранными бинарниками:

```sh
python3 -B tools/distill_synthetic_benchmark.py BEFORE_BINARY AFTER_BINARY --batch-archive
```

Стенд создаёт отдельные temp HOME и SQLite-архивы, 100 сессий с одной
assistant-записью по 256 ASCII-байт и три сессии с одной записью по 60000 байт
(`L`, кавычка, обратный слеш, перевод строки, повторённые 15000 раз).
Провайдер — loopback HTTP fake с пустым `facts`, окно 16384, максимум сессий
1000. Модели, настоящие CLI и пользовательские архивы не используются.

Сравнение исходного `05932b2` (содержит обе правки Claude-адаптера) и E5.8
`4dcc132` на этом стенде:

| Показатель | До E5.8 | E5.8 |
| --- | ---: | ---: |
| Вызовы для 100 мелких сессий | 100 | 2 |
| Вызовы для 3 больших сессий | 15 | 15 |
| Все вызовы | 115 | 17 |
| Суммарные session data, байт | 349 922 | 350 275 |
| Суммарные промпты, байт | 632 132 | 392 656 |
| Максимальный промпт, байт | 25 243 | 25 243 |

Число вызовов уменьшилось на 85,2%. Небольшой рост session data объясняется
новой оболочкой `sessions`; сокращение промптов — меньшим числом повторений
системной инструкции. Метрика prompt bytes не включает отдельную JSON schema,
HTTP framing и внутренний системный промпт подписочного клиента. Стенд измеряет
пакетирование, а не качество извлечения или точные токены/лимиты подписки.
Для реального архива число вызовов следует получать через `--dry-run` с
выбранным провайдером, фильтром ролей, курсорами и пределом сессий.
